# Lumiere — підготовка до самостійної роботи

## Реалізовано в коді

- 6 HTML-сторінок: `index.html`, `catalog.html`, `about.html`, `account.html`, `privacy.html`, `returns.html`; семантичні секції, мобільна навігація, внутрішні посилання.
- Дві теми з перемикачем у спільній шапці. Тема зберігається в `localStorage`; клас `html.dark` дає можливість застосовувати утиліти Tailwind `dark:`. Джерело: `tailwind-source.css`; локальні скомпільовані утиліти: `css/tailwind-components.css`.
- Банери темної теми з наданих фотографій: `assets/images/hero-dark.jpg`, `assets/images/about-dark.jpg`; читабельність і адаптивне кадрування: `css/theme-polish.css`.
- Інтерактивний каталог, обране, кошик, швидкий перегляд, форма з перевіркою, підбір розміру.
- Розширений віджет підбору сукні з чотирма параметрами й обробкою некоректних значень: `js/style-finder.mjs`, `js/style-matcher.mjs`.
- Swiper.js і Fancybox через CDN на головній (`js/lookbook.js`). Якщо CDN недоступний, горизонтальна галерея та індикатори працюють як запасний варіант; фото відкривається за посиланням.
- JSON mock-дані та асинхронне завантаження `fetch/async-await`: `data.json`, `js/mock-content.js`, блок «Наша філософія» на сторінці «Про нас». Статичний текст залишається, якщо запит не спрацював.
- SEO: title, description, canonical, Open Graph, `robots.txt`, `sitemap.xml`.
- Автоматизовані перевірки: `node --test tests/*.test.mjs`; сценарій GitHub Actions `.github/workflows/deploy.yml`.

## Візуальні виправлення темної теми

1. Пошук: акуратне поле та чіткий SVG-значок лупи.
2. Головний банер: зображення кадрується від верхнього краю; модель не обрізається зверху.
3. Блок «Переваги»: темні картки і при наведенні, видимі іконки та написи.
4. Lookbook: видимі індикатори галереї, контрастні підписи та кнопка збільшення.
5. Іконки акаунту, кошика, обраного: без білого фону при наведенні.
6. «Про нас»: темний фон, світлі читабельні заголовки та FAQ, стримані hover-ефекти.
7. Збережені світлий дизайн, анімації, кошик, модальні вікна, валідація та Size Advisor.

## Що ще потребує реальних дій перед здачею

- **Публікація:** скопіювати файли у свій чинний Git-репозиторій, не втрачати `.git`; зробити коміт і `git push`, перевірити реальний деплой Vercel або Netlify. Новий ZIP сам по собі не оновлює сайт в інтернеті.
- **Lighthouse:** зробити власні заміри на мобільному та десктопі, прикласти скриншоти й описати знайдені недоліки. Високі бали не можна гарантувати за локальними тестами.
- **Аналіз доступності:** перевірити контраст, клавіатуру, модальні вікна та форму в опублікованому середовищі.
- **GitHub Actions:** деплой із workflow запускатиметься лише після налаштування потрібних секретів Vercel. Якщо Vercel уже інтегрований із GitHub, не дублюйте автоматичний деплой без потреби.
- **Аналітика:** для GA4 або іншого сервісу потрібен ваш реальний ідентифікатор вимірювання; фальшивий трекер не додано.
- **ШІ-медіа:** банери отримані від користувача, не слід називати їх згенерованими ШІ без підтвердження; у звіті відобразіть фактичне джерело.
- **Документація:** у звіт самостійної роботи додайте дослідницький бриф, технічний опис, правдивий промпт-паспорт, свої скриншоти, результати аудиту, посилання на GitHub/сайт, висновок.
- **Демо-режим:** авторизація, оплата та замовлення не мають серверної частини — це прийнятно для навчального MVP за умовою самостійної роботи, але про це потрібно чесно сказати на захисті.

### Локальний запуск

Відкрийте **папку `Lumiere`** у VS Code і запустіть `index.html` через Live Server. Для `fetch` і ES-модулів потрібен локальний HTTP-сервер, а не відкриття через `file://`. Перевірте теми і всі кнопки, форми та інтерактивні віджети. Перевірка JavaScript: `node --test tests/*.test.mjs`.
